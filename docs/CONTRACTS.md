# Контракты модулей

Меняет только ведущий агент. Поток, которому нужно изменение, описывает его в отчёте.

## Планетная система и температура (2026-10-15)
- `BodyID`: Сол, Велла, Терра, Луна, Арда, Тарос. Родитель задаёт дерево сфер влияния; координаты корабля всегда относительно активного тела.
- `CelestialBody`: собственные радиус, μ, SOI, вращение, атмосфера и температурный профиль в Кельвинах; `hasSolidSurface == false` запрещает посадку на звезду и газовый гигант.
- `World.position/velocity(of:relativeTo:at:)` — единые эфемериды для физики, карты и полёта. `convert` сохраняет абсолютное положение и скорость при любом переходе SOI.
- `World.thermalEnvironment` отделяет температуру газа от радиационной среды в вакууме. Нагрев деталей учитывает атмосферу, поток, излучение и теплопроводность; на рельсах нет конвективного нагрева от скорости.
- Новые планеты — рабочие тела в обычной симуляции. Экономика, контракты, EVA и сбор научных данных из `CAREER_ECONOMY.md` / `MISSION_CATALOG.md` остаются планом отдельной реализации.

## Поток данных за кадр
```
UI (C) ── ControlInput, FlightCommand ──▶ FlightSimulation (A)
                                              │ advance(realDelta) → [SimEvent]
                                              ▼
                              WorldSnapshot + [SimEvent]
               ┌──────────────┬───────────────┼──────────────┐
          Renderer (B)     HUD (C)        Audio (D)     Haptics (D)
               ▲
UI (C) ── CameraInput ──┘
```
Игровой цикл (главный актёр, частота кадров из настроек): ввод → `advance` → раздать снимок и события. Физика не знает об Apple-фреймворках; остальные потоки не меняют физическое состояние.

## Физика — `Packages/OrbitPhysics/Sources/OrbitPhysics/Contracts.swift`
- `Vec3`, `Quat` — Double, СИ.
- Координаты корабля — инерциальная система с центром в `VesselState.body`; Терра вращается вокруг +Z (`WorldSnapshot.terraRotation`), Луна — круговая орбита в плоскости XY (`lunaPosition`).
- Ориентация: `attitude` переводит оси корабля (нос = +Y) в инерциальные.
- `FlightSimulation.advance(realDelta:)` сама дробит шаг (≤ 0.02 с), учитывает ускорение времени и авто-сброс (`SimEvent.warpReset`).
- `ControlInput` — непрерывный ввод (тяга 0…1, оси −1…1, RCS). `FlightCommand` — кнопки (ступень, SAS, ускорение, парашют).
- `FlightTelemetry` — готовые числа для HUD и звука (включая `stages: [StageInfo]` — Δv, TWR, топливо по ступеням (`fuelMass`/`fuelCapacity` в кг, `hasLiquidEngine` для смешанных ступеней); тягу, РДТТ, плотность, нагрев, перегрузку); HUD сам ничего не считает.
- `FlightTelemetry.navball` — маркеры навбола уже в осях корабля; `pitch/heading/roll` — относительно горизонта; `chute`, `chuteSafe`; `warpIndex` в `TimeWarp.levels` (×1–4 физическое, ×10–100 000 рельсы) и `warpBlocked`.
- `FlightTelemetry.nextStageAction` — точное следующее действие: `.ignite`, `.separate`, `.armChute`, `.none`; HUD и подсказки не определяют его по числу секций.
- `VesselAssembly.empty`, `insert(_:into:at:)`, `move(_:from:to:)` — осевая сборка (до 5.2; ангар 5.2 — `VesselEditing`); крепления 0…count, перенос использует индекс крепления до удаления исходной детали. Сохраняется прежний формат `VesselDesign.parts`.
- `stages[0]` — текущая ступень; отдельного номера ступени нет.
- `FlightTelemetry.mission: MissionRecord` — итоги полёта с момента старта (макс. высота/скорость/перегрузка, космос, орбита, SOI Луны, орбита Луны, посадка на Луну, возврат из космоса) — для экрана результата.
- `VesselDesign.issues() -> [DesignIssue]` — проверка проекта в ангаре; `isBlocking` — старт запрещён, `text` — строка для UI.
- `SimEvent` — одноразовые события шага для звука, вибрации, эффектов, подсказок.
- Узел манёвра (этап 5): `FlightCommand.setManeuver(ManeuverNode?)` — поставить/изменить/удалить узел активного корабля (один узел); `warpToManeuver` — рельсы до узла, сброс до ×1 за `ManeuverStatus.warpLead` с до начала прожига (`WarpResetReason.maneuver`). `SASMode.maneuver` — держать нос по оставшемуся импульсу. `FlightTelemetry.maneuver: ManeuverStatus?` — время до узла, Δv полный и оставшийся (уменьшается тягой), время прожига, начало прожига, `isDone` (только при импульсе узла ≥ 1 м/с); `navball.maneuver` — направление оставшегося импульса. Остаток = Δv узла − сожжённое тягой с момента постановки узла (правка узла посреди прожига сожжённое не теряет; удаление узла его обнуляет). Без тяги (`burnTime` = ∞) `timeToBurn` = `timeToNode`.
- `FlightSimulation.predictTrajectory(maxPatches:)`, `predictManeuver(_:maxPatches:)` — прогноз патченными кониками для карты. `MapMarkers.compute(_:afterManeuver:)` — Ап/Пе, AN/DN, SOI, падение по участкам (`MapMarker`, координаты в инерциальной системе тела участка; `soiExit(b)` — тело, из SOI которого выходим). Число участков прогноза — `TrajectoryPredictor.defaultMapPatches` (4).

- `Terrain.craterShade(body:direction:)` — оттенок малых кратеров Луны −1 (дно) … +1 (вал), 0 вне кратеров и на Терре; малые кратеры (25 м–2.5 км) входят в `Terrain.height`, биом не меняют.

- РСУ (Б4): детали `PartID.rcsBlock` (`PartKind.rcs`: сопла + свой запас монотоплива; `thrustVacuum` — тяга на одно направление, Isp монотоплива) и `.m100` (`PartKind.monoTank`). Монотопливо хранится в `fuelMass` этих деталей, общее на весь корабль (через разделители тоже), в Δv ступеней не входит. `FlightCommand.setRCS(Bool)`; при включённом РСУ `ControlInput.translation` (x — правый борт, y — вперёд по носу, z — вверх/спина) даёт тягу `блоков × тяга × команда` по каждой оси, а поворот (ручной и SAS) получает добавочный момент от сопел; расход — по Isp. Без блоков или монотоплива РСУ молчит. Тяга РСУ уменьшает остаток узла манёвра; работающие сопла блокируют рельсы (`.thrust`). `FlightTelemetry.rcs: RCSStatus` (есть ли блоки, включено, монотопливо кг/ёмкость, работают ли сопла). `VesselState.rcsTranslation` / `rcsRotation` — команда на сопла в этом кадре (для струек рендера), нули — молчит.
- `VesselState.parts` (сверху вниз), `firingEngines` (индексы деталей с факелом), `chute`, `chuteDeploy` 0…1 — для рендера корабля и отделённых ступеней.
- Оси корабля: нос +Y, спина +Z, правый борт +X; pitch>0 — нос к +Z, yaw>0 — к +X, roll>0 — правый борт вниз. На площадке +X — восток, +Z — юг. `position` — нижняя точка стека; `angularVelocity` — инерциальная.

## Приложение — `App/Core/AppContracts.swift`
- `FlightRenderer` (B): floating origin — рендер вычитает позицию активного корабля и переводит в Float сам. Принимает `CameraInput` от C.
- `FlightAudio`, `FlightHaptics` (D): реагируют на снимок и события, выключаются флагом `isEnabled` (из `GameSettings`).
- `FlightFeedback` (ведущий): каждый кадр раздаёт снимок рендеру (`renderer.update`), звуку и вибрации; жесты камеры из UI идут через `feedback.camera(_:)` и `feedback.cameraMode`.
- `GameFlow` (ведущий): экран `hangar`/`flight`, текущий `design` (автосохранение в Documents/hangar.json через `DesignStore`), `launch()`, `returnToHangar()`, `makeSimulation()`, `flightID` — ключ нового полёта. Без `-screen` игра открывается в ангаре.
- `HangarPreview` (B): `show(parts:selected:)`, `apply(CameraInput)`; реализация `HangarScene` + SwiftUI `HangarSceneView(scene:)` — в `App/Render/`.
- `FlightFeedback.stop()` — выход из полёта: звук, вибрация и наклон выключены.
- `DemoScenario` (ведущий): аргумент запуска `-screen hangar|flight|ascent|staging|orbit|lunaApproach|lunaSurface|lunaDescent|chute|landed|crash` — стартовое состояние для CI-скриншотов и отладки (`screens.txt` — список снимаемых сцен).
- `MapModel` (ведущий, `App/Core/MapModel.swift`): владеет `FlightHUDModel` (`map`), каждый кадр `update(sim:now:)` — прогноз ≤ 4 Гц (при правке узла ≤ 30 Гц), отдаёт `MapSnapshot` рендеру (`updateMap`) и оверлею (`snapshot`); `isOpen`, `focus` пробрасываются в рендер; `project`, `orbitPick`, `setViewSize` — через рендер.
- `FlightRenderer` карта (B): `isMapMode` — вместо полёта тела в масштабе карты, орбиты (текущая — по участкам, после узла — пунктир/другой цвет, участок у Луны — фиолетовый, возврат к Терре — оранжевый), корабль-значок, SOI Луны; жесты `apply` крутят камеру карты вокруг `mapFocus`. `project` и `orbitPick` — для оверлея C (подписи отметок, тап по орбите).
- Сцены карты: `-screen map|mapManeuver|mapLuna` (`DemoScenario.opensMap`, `mapFocus`).
- `GameSettings`: частота кадров 60/90/120 (по умолчанию 90), звук, вибрация, наклон (выкл.), подсказки первого полёта (вкл.).

## Обучение «Первый полёт» (2026-10-13)
- Физика: `FlightCheckpointing` (`checkpoint() -> SimCheckpoint`, `restore(_:)`) — полное состояние `FlightSim` для отката шага; реализует только `FlightSim` (`sim as? FlightCheckpointing`), у моков и `ScenarioFlight` — nil, повтор шага тогда недоступен.
- Ведущий (`App/Core/GameFlow.swift`): `TutorialID` (`.firstFlight`, `title`, `design` = «Орбита»), `GameFlow.tutorial`, `startTutorial(_:)` (проект ангара не меняется; `makeSimulation` строит корабль урока), `launch()`/`returnToHangar()` сбрасывают урок. `TutorialProgress` (UserDefaults): `wasOffered`/`markOffered()` — предложение при первом запуске показано, `isFirstFlightDone`/`markFirstFlightDone()`. Сцена `-screen tutorial` — урок на площадке (CI).
- C (`App/UI/Tutorial/`): контроллер урока — шаги из макета (артефакт «Орбита — обучение «Первый полёт»»): знакомство (пауза), тяга MAX (ждём), Пуск (ждём), вертикально до 1 км (живая), разворот ▶ до 80° (ждём), следовать метке до 10 км (живая), отделение (пауза при пустой ступени), Ап 80 км — тяга 0 (ждём), ускорение до Ап (ждём), скругление (живая), итог (пауза). Виды шагов: `pause` — игра на паузе, затемнение с вырезом вокруг элемента, пузырь с кнопкой; `wait` — то же, ждёт действия игрока (на паузе физика стоит, но действие — тяга/кнопка — принимается; после него пауза снимается); `live` — плашка без затемнения, полёт идёт. Ошибка шага (нос > 15° от цели дольше 3 с или Ап падает) — красная плашка «Повторить шаг»: `restore` контрольной точки начала шага и пауза. Пороги — `AscentGuide`, шаги — согласованы с `MissionChecklist`. Подсвечиваемые элементы HUD отдают свои рамки через anchor preference (ключ — элемент урока). Пока идёт урок, подсказки первого полёта (`HintBanner`) и помощник подъёма в строке статуса не дублируют урок. Вход: предложение при первом запуске (ангар, если `!wasOffered`), «Обучение» в ангаре и в меню паузы. Итог — `markFirstFlightDone()`, «В ангар».

## Конструктор 5.2 (2026-10-13)
Типы и сигнатуры — `Packages/OrbitPhysics/Sources/OrbitPhysics/DesignTree.swift` (ведущий), тела «A» — поток A.
- `VesselDesign` — дерево: `nodes: [DesignPart]` (id, деталь, родитель, узел `top/bottom/radial`, азимут и высота для бока, группа симметрии, ступень активации), порядок — обход в глубину от корня; `parts` — вычисляемый список в том же порядке; `customStaging`. `init(name:parts:)` — линейный стек сверху вниз (старый формат и пресеты). JSON v2 (`nodes`); старый `{"name","parts"}` читается как линейное дерево с авто-ступенями.
- Детали 5.2: `decouplerRadial` (`.decoupler`, только бок), `fairing`/`fairingXL` (`.fairing`, ось), `fin` (`.fin`, только бок). `PartSpec.mount` — `.axial/.radial/.any`. `maxParts` = 60.
- Раскладка `layout() -> [PartPlacement]`: центр в осях корабля, `outward` у боковых; начало — на оси корня у самой нижней точки (= `VesselState.position`). Осевая деталь на `top`/`bottom` соосна родителю, вплотную; боковая — ось параллельна, центр на `радиус родителя + радиус (толщина) детали` по азимуту, середина детали на высоте `height` родителя (стабилизатор — внешней кромкой наружу, разделитель — плитой к родителю, ребёнок разделителя — снаружи плиты).
- Ступени активации: `DesignPart.stage` (0 — первая), `stageGroups`, авто-правило `autoStaged()` (для линейных стеков — прежняя последовательность кнопки «Ступень»). Активация ступени: зажечь её двигатели, сработать разделители (каждый отделяет своё поддерево от родителя), сбросить обтекатели, взвести парашют.
- Физика корабля по дереву (A, `Ship` внутренний): топливо — группы деталей, связанные без разделителей (разделитель перекрывает перетекание в обе стороны), жидкостные двигатели берут из баков своей группы (пропорционально остаткам), РДТТ — своё. Тяга — сумма по `+Y`; момент тяги `Σ (pᵢ − ЦМ) × Fᵢ` → угловое ускорение `τ / I⊥` (I⊥ — детали как цилиндры относительно ЦМ), добавляется в `attitude`; у соосного стека ровно ноль (прежнее поведение). Сопротивление: по «колоннам» (ось корня + каждая боковая ветвь) `0.5·π/4·ΣD²`, колонна под обтекателем ×0.7, стабилизатор +0.05 м²; у линейного стека без обтекателя — прежнее. Стабилизаторы ниже ЦМ: устойчивость носом вперёд (`retroStable` = false) и восстанавливающий аэромомент × (1 + 0.5·число стабилизаторов).
- Отделение: разделитель уносит своё поддерево (с собой) — новый корабль-обломок со своей раскладкой; активным остаётся компонент с корнем; `position` пересчитывается так, чтобы корабль не сдвинулся в пространстве. Сброшенный обтекатель — тоже обломок.
- Телеметрия: `stages` — оставшиеся ступени активации, `[0]` — последняя активированная (до старта — первая); Δv — пошаговым сжиганием по группам топлива до отделения следующей ступени; `StageInfo.parts` — что срабатывает в ступени. `nextStageAction`: `.separate` (есть разделитель/обтекатель), иначе `.ignite` (двигатели), иначе `.armChute`. `VesselState.layout` — раскладка (обломков тоже).
- `design.stageInfos()` — по ступеням активации (`[k]` ↔ `stageGroups[k]`), [0] — у земли. `markers(stage:)` — ЦМ, ЦТ, плечо асимметрии, ЦД. `issues()` дополнительно: `.asymmetricThrust` (плечо > 0.1 м у ступени), прежние проверки — по группам/ступеням.
- Правки `VesselEditing`: `attachTargets(for:symmetry:in:)`, `canAttach`, `attach(_:to:symmetry:in:) -> [Int]`, `remove`, `move`, `setStage`, `swapStages`, `resetStaging`. Симметрия ×1–4 для бока; к детали из группы симметрии — ко всем копиям.
- Рендер (B): `VesselVisual` строит корабль по `parts` + `layout` (пусто — прежний стек), факелы/струйки/купол/эффекты — по раскладке; модели новых деталей. `HangarPreview`: `show(design:selected:)`, `apply`, `project(_:viewSize:)`, `pickPart(at:viewSize:) -> id`.
- UI (C): ангар-конструктор — каталог (вкладка «Аэро»: обтекатели, стабилизаторы; боковой разделитель — в «Разделители»), точки крепления поверх 3D (через `project`), симметрия ×1–4, выделение тапом, удалить/перенести, редактор ступеней (перетаскивание деталей между ступенями, «Авто»), маркеры ЦМ/ЦТ/ЦД, Δv/TWR по ступеням, предупреждения; HUD-стопка ступеней — по `StageInfo.parts`.

## Конструктор 5.2 — согласованный макет (2026-10-13)
Макет: артефакт «Орбита — космоцентр и конструктор» (v3, согласован пользователем). Дополняет раздел выше.
- Физика (A): `DesignPart.rotation` (градусы: x тангаж, y крен, z рыскание), `offset` (м), `mirrored`; `PartPlacement.orientation`; тяга двигателя — по его оси из сопла (наклон → поперечная сила и момент). `VesselEditing.setRotation`, `setOffset` (не дальше габарита родителя), `setRoot` (раскладка не меняется), `attach(..., symmetry:, mirror:, in:)` — зеркальная симметрия ×2. Копии симметрии поворачиваются согласованно (пара не даёт момента).

- Экипаж в проекте (A): `VesselDesign.crewSeats: [Int: [String?]]` — явная рассадка по `DesignPart.id` кабины (`PartSpec.crew` мест), JSON-ключ `crew` (необязательный, старые проекты — автоматически). `seating(roster:) -> [CrewSeat]` — все места кабин в порядке `nodes`; кабины без записи заполняются по порядку отряда теми, кто ещё не сидит; неизвестные id и повторы — пусто; записи удалённых деталей игнорируются. `crew(roster:)` — сидящие по порядку. `setSeat(partID:index:memberID:)` — сначала делает текущую рассадку явной, затем пересаживает (член экипажа покидает прежнее место); nil — освободить.
- Экипаж в полёте (ведущий): при старте `GameFlow` берёт `design.crew()`; уроки и сценарии — экипаж их корабля по той же рассадке (`-screen` сцены могут задать экипаж). Корабль без кабин или без людей — без портретов. Отдельный учёт гибели/выживания и отделённых кабин — нет (вне этапа).
- Реакции (A): `CrewReactor(crew:)`, `update(telemetry:events:dt:) -> [CrewCue]` — каждый кадр с реальным `dt` (на паузе не вызывается); `reactions: [CrewReaction]` (настроение, сила 0…1, время в настроении). Настроения `CrewMood` по приоритету: `crash` > `panic` > `strain` > `joy` > `awe` > `calm`. Более важное включается сразу; менее важное — не раньше 1.5 с в текущем. Пусть `f = 1 + 0.5·(1 − храбрость)` (трус до 1.5× чувствительнее):
  - `crash`: событие `.crash` или `situation == .crashed` — до конца полёта, сила 1.
  - `panic`: `thermal.hottest > 0.7/f`; событие `.partDestroyed` — 4 с; падение — купол не раскрыт (`chute != .open`), не на грунте, `verticalSpeed < −22/f` м/с и время до удара `heightAboveTerrain / −verticalSpeed < 8·f` с. Сила — max(нагрев, 1 − время до удара/(8·f)), не меньше 0.6.
  - `strain`: `gForce > 2.5/f`; напор `dynamicPressure > 0.7 ×` наибольшего напора полёта при нём ≥ 15 кПа; событие `.maxQ` — 2 с. Сила — max((g − 1)/4, q/40 кПа), 0…1.
  - `joy`: `.touchdown`/`.splashdown` без аварии — 6 с; первый вход в `situation == .orbiting` — 4 с.
  - `awe`: первый выход выше атмосферы тела (`atmosphereDensity == 0`, не на грунте) — 6 с, сила 1; невесомость — `atmosphereDensity == 0`, `gForce < 0.1`, `thrust == 0`, не на грунте — пока длится, сила 0.5.
  - `calm`: остальное (площадка до старта, посадка после радости).
  Сигнал `CrewCue(memberID, mood)` — при входе в настроение, кроме `calm`; не чаще раза в 3 с на члена экипажа для одного настроения.
- Приложение (ведущий): `CrewModel` (`App/Core/CrewModel.swift`, `@Observable`) — владеет `CrewReactor`, обновляется из `FlightHUDModel` после `advance` (не на паузе), публикует `members` и `reactions` для HUD, передаёт `cues` в `FlightFeedback.crew(_:)` → звук и вибрация. `override: CrewMood?` — принудительное настроение для сцен CI. Сцены `-screen crewGallery` (все персонажи × все настроения крупно, из настоящего компонента) и `crewCalm|crewStrain|crewAwe|crewPanic|crewJoy|crewCrash` (HUD на подходящем полёте с принудительным настроением).

Короткие синтезированные голосовые звуки без слов: `strain` — натужное «ммм», `awe` — «ух», `joy` — «ура», `panic` — вскрик, `crash` — «ой»; тон по члену экипажа; громкость ниже рокота двигателя; вибрация — лёгкий двойной тап на `joy`, резкий на `panic`/`crash`. ## Простая карта: манёвр по цели (2026-10-13)
Макет согласован пользователем 2026-10-13 (inline-виджет «orbita_simplified_map_and_tutorial», часть 1): слева «Куда летим?» — кнопки целей, справа «Результат» (итог цели, Δv, через сколько, «−», ползунок, «+», «Эксперт»), снизу справа большая «▶ Выполнить манёвр», рядом «Удалить». Ручки Δv, оси ПРОГР/НОРМ/РАД, шаги ±10/±1/±0.1, сдвиг по времени и тап по орбите — только в режиме «Эксперт».
- Физика (A), `Packages/OrbitPhysics/Sources/OrbitPhysics/ManeuverPlanner.swift`:
  - `public enum ManeuverGoal: String, CaseIterable, Sendable, Hashable, Codable { case toLuna, circularize, changeOrbit, returnHome }`.
  - `public enum ManeuverPlanner`:
    - `static func availableGoals(body: BodyID, state: StateVector, time: Double) -> [ManeuverGoal]` — дёшево (без прогнозов), порядок = порядок кнопок. Терра, замкнутая орбита с Пе выше атмосферы: `toLuna` (если Ап < половины радиуса орбиты Луны), `circularize` (если e > 0.01), `changeOrbit`. Терра, суборбитально (Пе в атмосфере/под землёй), Ап выше атмосферы и Ап ещё впереди: `circularize`. Луна, незамкнутая или Ап за SOI: `circularize` (захват у Пе). Луна, замкнутая в SOI с Пе выше 6 км: `returnHome`, `circularize` (e > 0.01), `changeOrbit`. На грунте и прочее — пусто.
    - `static func plan(_ goal: ManeuverGoal, body: BodyID, state: StateVector, time: Double) -> ManeuverNode?` — узел цели: `toLuna` — перенос `DemoScenario.lunaTransferNode` (гомановская фаза + `tuneLunaPeriapsis` до Пе ≈ 30 км); `circularize` — в ближайшем апсисе (на суборбите и при подлёте к Луне — у Ап/Пе по правилу выше), прогрейд/ретрогрейд до круговой; `changeOrbit` — в ближайшем Пе, прогрейд +20 м/с; `returnHome` — с орбиты Луны: момент и прогрейд, при которых после выхода из SOI Пе у Терры ≈ 35 км (подбор по ≤ 1 обороту, секущие по Δv). nil — цель невыполнима. Время узла ≥ `time + 30`. Бюджет: ≤ ~60 прогнозов `predict` на вызов (на iPhone < 0.3 с).
    - `static func fineStep(_ goal: ManeuverGoal?) -> Double` — шаг кнопок «−/+», м/с: `toLuna`, `returnHome` — 0.1; прочее и nil — 1.
    - `static func outcome(_ goal: ManeuverGoal?, trajectory: Trajectory) -> ManeuverOutcome` — итог по прогнозу после узла (`MapSnapshot.maneuver?.trajectory`).
  - `public struct ManeuverOutcome: Sendable, Hashable { public enum Kind: Sendable, Hashable { case lunaPeriapsis(Double), terraPeriapsis(Double), orbit(body: BodyID, apoapsis: Double, periapsis: Double), noEncounter(BodyID), impact(BodyID) }; public var kind: Kind; public var isGood: Bool }`. Годно: `toLuna` — встреча с Луной, Пе 15–60 км; `returnHome` — возврат к Терре, Пе 20–50 км; `circularize` — e < 0.02 и не падение; `changeOrbit`/nil — без падения и Пе выше атмосферы/6 км. Высоты — над уровнем моря, м; Ап незамкнутой — `.infinity`.
  - Коррекция (добавлено после сквозного теста: прожиг 47 с даёт Пе у Луны 323 км вместо 30): `static func correction(_ goal: ManeuverGoal, body: BodyID, state: StateVector, time: Double) -> ManeuverNode?` — для `toLuna` (на орбите Терры после перелётного прожига, встреча есть или почти есть) и `returnHome` (после выхода к Терре или ещё у Луны на отлётной траектории): узел в `time + 60`, импульс (прогрейд, при необходимости радиальный) подобран секущими так, чтобы итог цели попал в середину годного диапазона (30 и 35 км); nil — итог уже годен (`outcome(...).isGood` по прогнозу без узла) или подобрать нельзя. Δv коррекции обычно единицы м/с, предел 100 м/с. Бюджет — как у `plan`.
- Приложение (ведущий): после `.done` автопрожига с целью `toLuna`/`returnHome` модель вызывает `correction` и, если узел есть, сразу выполняет его (фаза «Коррекция»); не больше 2 коррекций подряд.

  - Модель: `mapExpert: Bool` (UserDefaults `mapExpert`, по умолчанию false; в уроках всегда false); `maneuverGoal: ManeuverGoal?` (ставится `planManeuver`, сбрасывается удалением и правкой в «Эксперт»); `availableGoals` (обновляется не чаще 4 Гц); `planManeuver(_:)` (nil → тост «Сейчас не получится»); `nudgeManeuver(by:)` — прогрейд ± `fineStep`; ползунок — пружинящий «джог» через `ManeuverDrag` с масштабом `fineStep` (рукоять возвращается в центр, скорость — по отводу).

Тяги нет: `nextStageAction == .ignite` — `.stage`; ступень пуста и `.separate` — `.stage` (потом `.ignite`); `.armChute`/`.none` без тяги — ошибка «Не хватает топлива». `isDone` — тяга 0, `.setSAS(.hold)`, `.setManeuver(nil)`, тост «Манёвр выполнен». Отмена — игрок тронул тягу или кнопки ориентации, удалил/изменил узел, «Стоп».
  - Вид: простая панель по макету; в «Эксперт» — прежние `ManeuverPanel`, ручки, тап по орбите, `MapHintHost`. «Выполнить манёвр» во время автопрожига — «Стоп» + фаза («Летим к узлу 31:41», «Разворот», «Прожиг · ост 312 м/с»). Плашка узла вне карты показывает фазу автопрожига.
  - Обучение: новые `LessonElement.mapGoals`, `.mapExecute`; `.mapLuna` — кнопка цели «К Луне». Урок «Полёт к Луне»: шаги `tune`, `toNode`, `sasNode`, `burn` заменяются одним `execute` (цель `.mapExecute`, ждёт выполненного перелёта); остальное — без изменений (полная переделка уроков — следующая задача).

## Перелёт к планете (2026-10-15)
- Физика: `PlanetTransfer` (`PlanetTransfer.swift`). Цели `ManeuverGoal.toVella/toArda/toTaros` (`planet`, `toPlanet(_:)`, `planetGoals`). `availableGoals`: на орбите Терры с Пе выше атмосферы — в конце списка; на гелиоцентрической дуге (`.sol`) — только они.
- `plan` у Терры — `PlanetTransfer.departure`: ближайшее гомановское окно (`timeToWindow`, окно прошло ≤ 2 оборотов назад — ещё годно), точка орбиты по углу асимптоты, прогрейд до v∞, подбор прогрейда (золотое сечение по сближению, оборот −1/0/+1), при встрече — Пе прогрейдом. На `.sol` — `correction`.
- `correction` к планете: встреча есть — узел через 60 с после входа в SOI, секущие до Пе ≈ `targetPeriapsis` (рельсы + 30 км); не дотянуть или встречи нет — `courseCorrection` на середине оставшейся гелиоцентрической дуги, 3D-импульс Ньютоном до точки прицела (прицельный параметр для Пе, облёт по ходу), предел 1.5 км/с. `maxCorrections(goal)`: Луна/домой — 2, планеты — 3.
- `ManeuverOutcome.Kind`: `planetPeriapsis(BodyID, Double)` (годно — рельсы + 5…200 км), `planetApproach(BodyID, distance:, correction:)` (годно — оценка коррекции ≤ 300 м/с).
- Вехи: `MissionRecord.visitedPlanets/orbitedPlanets`, `Milestone.vellaSOI … tarosOrbit` (30 и 45 науки).
- Приложение: меню «К планете» в «Куда летим?» (планета · «окно через N дн»), итог «Сближение с Ардой … · коррекция ~X м/с» / «Пе у Арды …». Автопрожиг просит ускорение снова после смены SOI.

## Логичные уроки с подсветкой (согласовано 2026-10-13, делать после простой карты)
Принцип: один шаг — одно действие, в порядке настоящего полёта; одна строка «что и зачем», «Зачем?» — по желанию; нужная кнопка — яркая толстая пульсирующая рамка + стрелка от подсказки, остальное приглушено и не нажимается. У каждого шага с действием — своя цель подсветки (в т. ч. на карте).
- «Первый полёт» (цель — орбита 80 км): тяга MAX → ПУСК → вертикально до 1 км (только плашка) → разворот ▶ → держать нос у метки (навбол) → ОТДЕЛИТЬ → Ап 80 км, тяга 0 → «Карта» → «Скруглить орбиту» → «Выполнить манёвр» → финиш.
- «Полёт к Луне» (старт на орбите Терры): «Карта» → «К Луне» (фиолетовая линия, «Пе у Луны … ✓») → «Выполнить манёвр» → ускорить ▶▶ до Луны → у Луны «Скруглить орбиту» + «Выполнить манёвр» → посадка (SAS «Ретро» + тяга, плашка высоты и скорости).
- Шаг «Ап 80 км, тяга 0» (замечание пользователя по скриншоту: высотомер 35 км, а подсказка «высшая точка уже 80 км» — непонятно): текст «Сейчас N км. Двигатель уже разогнал ракету — дальше она сама долетит до 80 км. Тяга 0»; рядом с высотомером строка «Ап 80 км» (видна с подъёма), на шаге подсвечивается вместе с тягой.
- Реализация (C):
  - Подсказка — плашка сверху по центру (как в макете): «Шаг N из M» · одна строка действия · «Зачем?» (раскрывает 1–2 строки пояснения) · кнопка шага паузы («Понятно»/«Дальше») · «Выйти из урока» мелко. Цель — рамка 4 pt цвета `HUDPalette.advice`, пульсирует (масштаб/яркость, ~1 Гц), стрелка (пунктир с наконечником) от плашки к цели; затемнение вне цели в `pause`/`wait`, в `live` — только рамка и стрелка. Номер шага — по видимым шагам урока.
  - Новые `LessonElement`: `.apoapsis` (строка «Ап …» у высотомера), `.mapCircularize` (кнопка цели «Скруглить орбиту»); `.mapLuna`, `.mapExecute`, `.mapButton`, `.warp`, `.sas` — как есть.
  - Строка «Ап 80 км» у высотомера (`Altimeter.swift`/соседний вид): в полёте, когда есть орбита и Ап выше 1 км и не на грунте.
  - Автопрожиг: если рельсы заблокированы (атмосфера) и до прожига далеко — физическое ×4, а как только рельсы можно — `.warpToManeuver` (один раз). Нужно для «Скруглить» на подъёме.
  - «Все кнопки» (`ControlsTour`) — удалить урок из списка, кода и тестов; долгое нажатие (0.5 с) на кнопки HUD и карты показывает плашку-подсказку одной строкой (на 3 с) и НЕ выполняет действие кнопки; тексты — по одной строке на кнопку (можно взять из шагов тура).
- «Все кнопки» — убрать; вместо него долгое нажатие на любую кнопку HUD — всплывает одна строка, что она делает.

## Текстуры планет и навбол на карте (2026-10-14)
- `PlanetSurface` задаёт общий атлас кубосферы: 3×2 грани по 1024 px, поля по 8 px, итог 3120×2080. `uv(face:a:b:)` используется всеми LOD и картой; поля рассчитываются по продолжению направления грани, а не копированием другого биома.
- `scripts/bake-planets.py` запекает `Terrain.height`, `craterShade` и `Palette.terrainUV` в оригинальные PNG `TerraSurface` / `LunaSurface`. Для обновления географии/палитры перезапечь ассеты. В игре только асинхронная загрузка ресурсов; карта и полёт разделяют материалы. Геометрия и физика поверхности не меняются.
- Навбол доступен и в полёте, и на карте. Переключатель фокуса карты расположен над ним. Ручная тяга использует существующую модель HUD (в том числе отмену автопрожига).

## Мелкая фактура поверхности (2026-10-15)
- `TerrainMaterial` создаёт общий для карты и полёта `CustomMaterial` из PBR-материала с исходным цветовым атласом. `TerrainSurface.metal` восстанавливает связанное с телом направление из `PlanetSurface.uv`; базисы и tan-развёртка должны совпадать с `CubeSphere`.
- `custom.value`: x — радиус тела в метрах, y — 1 для Луны / 0 для Терры, z — размер грани, w — поле атласа. Фактура не зависит от локального центра патча, вращения тела, масштаба карты или floating origin.
- Диапазоны 256/32/4/0.8 м изменяют только цвет, шероховатость и нормаль. Экранные производные гасят неразличимые частоты; физический рельеф, береговая линия и меши не меняются. При недоступности Metal остаётся исходный PBR.
- `-planet-preview -flight-render -surface-closeup` снимает поверхность с высоты 160 м через полётный SceneRenderer. Маркер готовности требует активный CustomMaterial и видимый LOD 10; CI сохраняет кадр рядом с картой и общим планом.

## Типы топлива и газовая РСУ, первая поставка (2026-10-16)
SPEC «Топливо и ориентация (RCS)». Ксенон и перекачка — позже.

- `FuelType` (`Parts.swift`, Codable по rawValue): `kerolox` «Керосин + окислитель», `solid` «Твёрдое», `methalox` «Метан + окислитель», `mono` «Монотопливо», `gas` «Сжатый азот»; `title`, `isRCS` (mono, gas). `PartSpec.fuelType: FuelType?` — по детали: баки `.tank` (Т-*, Ю-64 — kerolox; МК-* — methalox), двигатели (РДТТ — solid; «Сполох» — methalox; прочие — kerolox), `.rcs`/`.monoTank` (Рой, М-100 — mono; «Бриз», А-50 — gas); остальные — nil (абляция экрана — не топливо). `PartKind` не меняется: газовые сопла — `.rcs`, баллон — `.monoTank` («бак топлива РСУ»).
- Новые детали: сопла ориентации «Бриз» (`.gasJet`, `.rcs`, 0.03 т + 0.01 т азота, 0.5 кН на направление, Isp 45/65), баллон азота А-50 (`.n50`, `.monoTank`, 0.06 + 0.08 т), баки МК-200 (`.mk200`, 0.09 + 1 т) и МК-400 (`.mk400`, 0.18 + 2 т), двигатель «Сполох» (`.spolokh`, 200 кН, Isp 280/350, 1.3 т). Технологии: `gasControl` «Ориентация газом» (5, от «Основ», столбец 1, строка 3), `methane` «Метан» (40, от «Тяжёлых ракет», столбец 4, строка 0).
- Ship: двигатель берёт только своё топливо из своей группы (секции без разделителей): `FuelSource.group(g, FuelType)`, `.solid(i)`. `fuel(group:type:)`, `capacity(group:type:)`. `liquidFuel(group:)`/`liquidFuel(in:)` — все баки `.tank` (как раньше). Старые детали — поведение без изменений.
- РСУ: запас каждого типа общий на корабль (через разделители). Блок тратит только своё топливо (`rcsMass(_:)`, `rcsCapacity(_:)`, `drawRCS(_:_:)`; `monoMass`/`monoCapacity`/`drawMono` — синонимы для mono). Поступательная тяга — Σ по типам с запасом (тяга блоков типа × команда); поворот: добавка к управлению по типу = (Σ тяги блоков типа / тяга «Роя») × `rcsRotationAccelPerBlock` / √(m_т/2 + 0.5) — с одним «Роем» как раньше. Нехватка топлива урезает долю своего типа.
- `RCSStatus`: +`gasMass`, `gasCapacity` (по умолчанию 0); `monoMass/monoCapacity` — только монотопливо; `available` — есть любые блоки; +`fraction` — общий остаток (mono+gas)/ёмкость.
- Ангар: `StageInfo.deltaVByFuel: [FuelType: Double]` — Δv ступени, разложенный по долям массового расхода каждого топлива (Σ = `deltaV`). `VesselDesign.rcsDeltaV() -> [FuelType: Double]` — Δv РСУ по типу на последней конфигурации (после всех ступеней), вакуум.
- `DesignIssue`: +`.wrongFuel(stage:fuel:)` — в секции двигателя есть баки, но не его топлива («Ступень N: двигателю нужно «Метан + окислитель»»); `.noFuel` — баков нет вовсе; `.monoWithoutRCS` — монотопливо без блоков на монотопливе; +`.gasWithoutJets` «Баллон азота без газовых сопел».
- UI (каталог: подписи топлива; ангар: Δv по топливу; HUD: шкала РСУ по типу) — только после макета и «да».
