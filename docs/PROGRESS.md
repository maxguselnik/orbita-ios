# Прогресс

Короткий файл: читается каждой сессией целиком. Держать до ~8 КБ; завершённое переносить в [HISTORY.md](HISTORY.md) (архив, при старте не читать).

## Правила (от пользователя)
- Каждая сессия и субагент получают минимальный бриф: цель, ветка, критерии, точные файлы/разделы — без истории; лишнего не читать.
- Каждая задача очереди — в новой сессии: с iOS-кодом — локальная на Mac в отдельном worktree, облачная — для физики и документов (2026-10-16).
- UI — сначала макет и «да» пользователя, после задачи — «ок».
- Не распыляться: одна задача за раз, новые просьбы — в очередь следующей задачи; мелкие правки ведущий делает сам, субагент — свежий с коротким брифом, `sonnet` где можно (2026-10-13).
- Отвечать по-русски, кратко, время — МСК. Скриншоты/видео пользователю не присылать.
- Тесты (2026-10-15): физика (`physics-linux`) в CI идёт всегда; `[build-only]` в сообщении коммита/заголовке PR пропускает только тесты приложения на macOS.

## Типы топлива и газовая РСУ (2026-10-16, ветка `claude/fuel-types-rcs-c26067`)
SPEC «Топливо и ориентация (RCS)», контракт — CONTRACTS.md «Типы топлива и газовая РСУ». `FuelType` (керосин, твёрдое, метан, монотопливо, азот): двигатель берёт только своё топливо из своей секции; старые детали и сохранения без изменений. Новые детали: сопла «Бриз» и баллон азота А-50 (технология «Ориентация газом», 5 науки, раньше «Роя»), баки МК-200/400 и двигатель «Сполох» (технология «Метан», 40, после «Тяжёлых ракет»). РСУ тратит топливо своего типа; Δv ступеней по топливам, Δv РСУ в ангаре; предупреждения «двигателю нужно …», «Баллон азота без газовых сопел». UI по согласованному макету: подписи топлива в каталоге, строка Δv по топливу у смешанной ступени, «РСУ … м/с» в сводке, шкала RCS — общий запас по типам. Тесты физики `FuelTypesTests` 16/16 (3 — по ревью F: пресеты без новых замечаний, Δv РСУ при сбросе РСУ ступенью и после выработки баков, два типа при пустом одном).
- Ограничения: момент РСУ — упрощённая модель (эквивалент «Роя» по тяге), не от положения блоков относительно ЦМ; модели «Бриза»/А-50 — как у «Роя»/М-100; струйки рисуются на всех блоках по общей команде (у «Роя» без монотоплива тоже); Δv РСУ в сводке — сумма по типам (каждый при полной массе другого); цен деталей нет (экономики ещё нет).
- Следующее: ксенон и ионный двигатель (этап 7, электричество); перекачка топлива между баками одного типа; момент РСУ от положения блоков; SAS через РСУ при нехватке маховиков; свои модели газовых деталей.

## Открытые проблемы
- 5.1: мягкие (прозрачные) эффекты могут ронять рендер на устройстве — тогда `SoftTextures.enabled = false`. Береговые линии на карте/с орбиты ступенчатые (биом по вершинам). Старые пояса дымки (`AtmosphereVisual` haze) — цилиндры вокруг камеры. Небо рисует горизонт на нулевом возвышении (на высоте настоящий горизонт ниже). «Ступень N из M» в сценах `-screen`, стартующих после отделения, считает M от текущего состава.
- Карта: пока открыта, эффекты событий полёта не обрабатываются (взрыв появится после выхода); на большом ускорении линии (4 Гц) могут отставать от тел.
- `FlightSim` с пустым списком деталей не защищён (ангар такой старт блокирует).
- Факел: основные слои непрозрачные; прозрачный ореол выключен по умолчанию (`VesselVisual.transparentPlumeGlow = false`).
- Порядок прозрачных объектов (дымка, облака, дым, ореол) RealityKit сортирует сам — возможны артефакты наложения.
- Дым ночью не темнеет (`daylight` не используется). Эффекты корабля — только у активного.
- Швы цвета между уровнями LOD; дымка — пояса вокруг камеры, не настоящее рассеяние (без шейдеров).
- Глубина: near 0.05–1000 м при far 1e7 и сетка LOD10 ~57 м против зазора камеры 1.5 м — проверить на устройстве артефакты у горизонта и камеру у грунта.
- Производительность рендера на устройстве не измерена (оценка до ~200 тыс. треугольников); каждый кадр пишутся трансформы всех видимых патчей; небо пересоздаёт материал при смене яркости.
- Сценарии `-screen` прокручивают автопилот синхронно (lunaSurface — несколько секунд) — только для CI/отладки.
- Наклон держит CoreMotion включённым на паузе.
- На `lunaSurface` Терры не видно в кадре (вероятно, посадка в кратере).
- Подстройка Пе у Луны ручкой Δv очень чувствительная (~70 км на 1 м/с). С `claude/luna-node-tune`: «К Луне» сам подбирает прогрейд под Пе ≈ 30 км (`TrajectoryPredictor.tuneLunaPeriapsis`, секущие, ≤ 12 прогнозов), цель шага `.tune` — 15–60 км, в панели узла есть ±0.1 м/с. Проверить на iPhone удобство доводки.
- Тесты: `AutoBurnIntegrationTests.lunaLessonPathFromTransferToCapture` идёт ~9 мин; `CraterTests.heightCallTime`, `RailsTests.advanceFrameCost` срываются по времени под нагрузкой.
- Чек-лист «Проверить на iPhone» (накопительный) — в [HISTORY.md](HISTORY.md).
