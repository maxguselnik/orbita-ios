# Прогресс

Режим: «авто» для всех этапов (с 2026-10-12 и визуальные — без остановок и без скриншотов пользователю); стоп только при блокере.

## Текущий этап
5 — карта и узлы манёвров, ветка `claude/orbita-stage-5-map`: сборка iOS в CI зелёная, 74 теста физики, ревью F без блокеров (замечания исправлены). Модели: код — субагенты на Sonnet 5.5, оркестрация и ревью — основная модель (`CLAUDE.md`).

## Передача другому агенту (как продолжить)
- Начать с `CLAUDE.md`, `docs/SPEC.md`, `docs/CONTRACTS.md`, этого файла. Этап 2 согласован и слит (PR #3), этап 3 — PR #4.
- Физика (Linux): если нет docker — Swift 6.0.3 из download.swift.org в `/opt/swift`, `swift test --package-path Packages/OrbitPhysics -Xswiftc -warnings-as-errors`. Иначе `docker run --rm -v "$PWD":/pkg -w /pkg swift:6.0-noble swift test --package-path Packages/OrbitPhysics -Xswiftc -warnings-as-errors` (или `swift test` с локальным Swift 6). 64 теста.
- iOS-код на Linux не собрать: пуш в ветку `stage*/**`, `claude/**` или PR запускает `.github/workflows/ci.yml` (macOS, Xcode 16.4, warnings-as-errors). Ошибки — в логе задания «iOS (macOS)».
- Скриншоты: задание «Скриншоты (симулятор)» (только на push) снимает сцены из `screens.txt` (`-screen <сцена>`), кладёт в артефакт и в ветку `ci-screens` (`<ветка>/<sha7>/`, публикация необязательна). Видео с этапа 4 не пишется (пользователю не нужно, задание быстрее). С этапа 4 задание падает, если приложение умерло за 8 с сцены (проверка через `launchctl list` в симуляторе) — это дымовой тест рендера.
- Не пушить в ветку, пока идёт «Скриншоты»: `concurrency` отменит прогон.
- CI: 2026-10-12 кончились минуты Actions для приватного репо (задания падали за 2 с с «spending limit»); репозиторий сделан публичным — минуты бесплатны. Если снова приватный — CI не запустится.
- Пользователь: отвечать по-русски, кратко; только landscape. С 2026-10-12 скриншоты и видео пользователю не присылать (CI снимает только скриншоты).

## Сделано
- Этап 0: правила, ТЗ, каркас XcodeGen, контракты, пустая сцена, CI.
- Этап 1:
  - A `OrbitPhysics`: Кеплер (универсальные переменные) и RK4, мир (вращение Терры, Луна на рельсах, рельеф, океаны, кратеры, биомы), каталог деталей и пресеты, `FlightSim` (тяга, Isp по давлению, сопротивление и аэромомент, маховики, SAS, ступени, парашют, посадка, SOI, ускорение ×1–4 / ×10–100 000 с авто-сбросом), узлы манёвров и прогноз траектории, автопилот.
  - C HUD по макету на настоящей физике (пресет «Орбита»), `MockFlight` для превью.
  - D процедурный звук (AVAudioEngine), Core Haptics, наклон (CoreMotion, по умолчанию выкл.).
  - E CI снимает скриншот и видео с симулятора, публикует в ветку `ci-screens`.
- Этап 2:
  - B `App/Render`: floating origin от камеры, импосторы далёких тел, кубосфера с квадродеревом патчей (фоновая генерация мешей, кэш 700), океаны и биомы, площадка с башней, Луна с кратерами, процедурные детали ракеты, факел, купол, отделённые ступени, небо темнеет с высотой, звёзды, Солнце; камера «свободная / следование / по курсу», не уходит под грунт.
  - C `App/UI`: жесты камеры на пустом месте, переключатель режима, 3D-навбол (Canvas) по центру, CADisplayLink с частотой из настроек, пауза при уходе в фон, исправлен крен двумя кнопками, HUD не пересобирается целиком.
  - A: рельсы у SOI без перебора (≤ 48 вызовов Кеплера за кадр, остаток не теряется), двухфазный парашют (пик ≤ 7 g), тяга на грунте блокирует рельсы; 45 тестов.
  - Ведущий: `DemoScenario` (`-screen`), раздача кадра рендеру.
- Оси корабля: нос +Y, спина +Z, правый борт +X; на площадке +X — восток. Джойстик вправо — поворот на восток.

- Этап 3 (ветка `stage3/integration`, PR #4):
  - Ведущий: `GameFlow` (ангар ↔ полёт, проект автосохраняется в Documents/hangar.json), `HangarPreview`, `FlightRenderer.reset()`, `FlightFeedback.stop()`, `MissionRecord` в телеметрии, сценарии `-screen hangar|chute|landed|crash`.
  - A: `MissionRecord` (макс. высота/скорость/перегрузка, космос, орбита, SOI и орбита Луны, посадка на Луну, возврат), `VesselDesign.issues()` (`DesignCheck.swift`), разбитый корабль вращается с телом, фазз 200 случайных проектов; 64 теста.
  - B: `HangarScene`/`HangarSceneView` (ангар, стек из моделей полёта, подсветка детали, кольца на разделителях, орбитальная камера), взрыв и обломки при аварии (непрозрачные, вращаются с телом), `reset()`.

## Открытые проблемы
- Карта: пока открыта, эффекты событий полёта не обрабатываются (взрыв появится после выхода); на большом ускорении линии (4 Гц) могут отставать от тел.
- Подсказка парашюта не учитывает незажжённый двигатель в последней секции (редкий проект).
- `FlightSim` с пустым списком деталей не защищён (ангар такой старт блокирует).
- Факел: основные слои непрозрачные, сверху полупрозрачный ореол (`VesselVisual.transparentPlumeGlow`); если на устройстве будут падения — отключать флаги эффектов по одному.
- Порядок прозрачных объектов (дымка, облака, дым, ореол) RealityKit сортирует сам — возможны артефакты наложения.
- Дым ночью не темнеет (`daylight` не используется). Эффекты корабля — только у активного.
- Швы цвета между уровнями LOD; дымка — пояса вокруг камеры, не настоящее рассеяние (без шейдеров).
- Глубина: near 0.05–1000 м при far 1e7 и сетка LOD10 ~57 м против зазора камеры 1.5 м — проверить на устройстве артефакты у горизонта и камеру у грунта.
- Производительность рендера на устройстве не измерена (оценка до ~200 тыс. треугольников); каждый кадр пишутся трансформы всех видимых патчей; небо пересоздаёт материал при смене яркости.
- Сценарии `-screen` прокручивают автопилот синхронно (lunaSurface — несколько секунд) — только для CI/отладки.
- Наклон держит CoreMotion включённым на паузе.
- На `lunaSurface` Терры не видно в кадре (вероятно, посадка в кратере).
