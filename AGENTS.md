# Орбита — инструкции для Codex

Правила проекта общие с Claude и лежат в `CLAUDE.md` — прочитай его целиком и следуй ему (язык, время МСК, стек, оркестрация, экономия контекста, тесты). Здесь только то, что касается Codex.

## При старте каждой сессии
1. `CLAUDE.md` — правила.
2. `docs/PROGRESS.md` — раздел «Передача» (на чём остановился прошлый агент, Claude или Codex), затем остальной файл.
3. `git status --short` и `git log -5 --oneline` — сверить с «Передачей».

## После каждой законченной задачи
Без напоминаний пользователя: перезаписать раздел «Передача» в `docs/PROGRESS.md` (5–8 строк: кто и дата МСК, ветка, что сделано, что проверено, что дальше, что не трогать) и закоммитить вместе с работой. Так Claude подхватит контекст, когда пользователь переключится.

## Отличия от Claude
Правила одни, но часть из них у Claude выполняют скиллы и хуки `.claude/`. Codex делает то же вручную:
- Перед правкой UI — макет по `.claude/skills/ui-mockup/SKILL.md` (картинка или HTML-файл в `docs/mockups/`), вопрос «так делать?», код — только после «да».
- После доработки — проверка по `.claude/skills/check/SKILL.md`: `scripts/run.sh`, тесты только изменённого кода (`scripts/affected-tests.sh`), полный прогон — по просьбе или при правке ядра.
- Правил `Packages/OrbitPhysics` — сразу прогони затронутые тесты физики (у Claude это делает хук).
- `reference/` не редактировать (у Claude это запрещает хук).
- Модели и субагенты из раздела «Оркестрация» — правила Claude; Codex работает сам, задачи — по одной.
- Ветки Codex — `codex/…`. Не работай в папке или ветке, где сейчас работает Claude; для параллельной работы — отдельный worktree.
