# Макет UI до реализации

Правка интерфейса без согласованного макета обычно уходит в переделку. Порядок жёсткий: **макет → «так делать?» → «да» → код**. Пока макет не согласован, не трогать Swift-файлы UI и не запускать субагентов на эту задачу.

## 1. Снять текущее состояние

Найти затронутую сцену (таблица сцен — в скилле `check`) и снять «как сейчас» (сборку не пересобирать, если `build/Build/Products/Debug-iphonesimulator/Orbita.app` уже есть):

```bash
scripts/ci-screens.sh <сцена>
```

Снимок `screens/<сцена>.png` прочитать через Read. Это основа макета: размеры и соседние элементы берутся с него, а не по памяти.

## 2. Нарисовать макет

Использовать inline-виджет (`mcp__visualize__read_me` → `show_widget`), SVG или HTML:
- кадр landscape iPhone 15 Pro: **852×393 pt**; учесть вырез (Dynamic Island) слева/справа и безопасные зоны ≈ 59 pt по бокам и 21 pt снизу;
- цвета — из `App/UI/HUD/HUDStyle.swift` (`HUDPalette`: панель `#0C1018` 85 %, рамка `#2A3446`, зелёный `#7CE38B`, акцент `#F2A03D`, SAS `#3EC6F0`, текст `#E8EEF5`, приглушённый `#8C98AA`), скругление 8–12, касание ≥ 44 pt;
- все надписи — по-русски и ровно теми словами, что будут в игре; без названий и ассетов KSP;
- фон — тёмно-синий космос с силуэтом планеты, чтобы видеть читаемость.

Если изменение затрагивает поведение (что появляется, когда и после чего), показать 2–3 состояния рядом: «до / после нажатия», «обычно / предупреждение».

Если есть настоящий выбор (два разумных варианта раскладки), показать варианты A и B бок о бок, с рекомендацией. Больше двух — нет.

## 3. Спросить

Под макетом кратко:
- что меняется (2–4 пункта);
- что останется как было;
- вопрос: «Так делать?» (или «A или B?»).

Ждать ответа. Правки по ответу — новый макет, снова вопрос.

## 4. После «да»

Реализовать ровно согласованное; отличия от макета, вынужденные кодом, назвать в отчёте. Затем скилл `check` с этой сценой и сравнение снимка с макетом.
